# Инструменты и MCP

Инструмент — действие с именем `сервер.действие`. Модель видит его, когда имя есть и в `access`, и в умении. См. [Разрешения](04-dostup.md).

## home

Группа `home` работает только внутри рабочей папки прогона. Префиксы задаёт `access.filesystem.home`.

| Инструмент | Действие |
| --- | --- |
| `home.list` | Каталог |
| `home.read` | Окно символов: текст, смещение, признак продолжения. Следующий вызов читает с `next_offset` |
| `home.write` | Текст из `arguments.content` в относительный путь, обычно под `out` |
| `home.run` | Псевдоним из `access.run.programs` |

Рабочий каталог `home.run` — корень рабочей папки. Аргументы передаются как есть, без оболочки и без поиска по `PATH`. Таймаут по умолчанию — 30 секунд, потолок — `access.run.max_timeout_ms`.

Исполняемый файл текущего процесса `kbshff` запускать нельзя.

Запуск идёт в изоляции ОС: пространства имён на Linux, AppContainer на Windows. Если изоляцию удержать нельзя, ответ — `SandboxUnavailable`, процесс не стартует. Повтор того же вызова изоляцию не создаёт.

В среду попадают разрешённые программы, их деревья установки и открытые папки рабочей области. Профиль пользователя и секреты не монтируются. На Linux доступна сеть компьютера, включая петлю. На Windows — исходящий интернет и локальная сеть, без петли.

## local_tools

`local_tools.search_docs` ищет по корню `filesystem.workspace`. `max_results` по умолчанию 8, не больше 100. `local_tools.read_file` читает файл из того же корня окном символов, как `home.read`.

Эти действия в репозиторий не пишут. Результат записывают через `home.write`.

## config

Группа `config` меняет сохранённый профиль в том же проекте: поручение, правила, умения, команды MCP, пределы, модель и список встроенных действий. Можно создать новый профиль.

Текущий процесс настройки не перечитывает. Правка видна со следующего запуска. Инструменты не читают `.env` и не возвращают ключи, заголовки и окружение MCP. Адрес модели текущего агента не меняют. MCP из этих действий не подключают. Разрешения папок, псевдонимы программ, биллинг и `event_mcp` не заменяют.

В шаблоне `init` они перечислены в умении `configure`. Текст умения просит менять профиль по просьбе пользователя. Если имена есть в разрешениях, вызов технически возможен. `agent.guide` есть на каждом прогоне и возвращает текст без живых настроек.

## MCP

MCP — отдельная программа или HTTP-сервис. Серверы перечисляют в `mcp`. `stdio` запускает команду. `http` ходит на адрес Streamable HTTP.

```yaml
mcp:
  - name: local
    transport: stdio
    command: "npx"
    args: ["-y", "mcp-server"]
    timeout_ms: 20000
```

Имя `local` становится первой частью инструмента, например `local.search`. Его добавляют в `allowed_tools`. Иначе модель его не вызовет, даже если сервер ответил на опрос.

```powershell
kbshff mcp discover --project-root . --agent demo
kbshff check --project-root . --agent demo
```

В студии серверы опрашиваются по одному: один сбой не скрывает остальные.

Процесс `stdio` стартует с очищенным окружением. В него попадают переменные, перечисленные в настройке сервера. Для запуска нужна рабочая песочница. `KUIBYSHEFF_ALLOW_UNSANDBOXED_MCP=1` обходит её и остаётся для отладки.

HTTP-сервер может взять статический заголовок или OAuth. Секрет кладут в переменную окружения, имя которой записано в конфиге.

Калькулятор цены из `billing.mcp` модели не показывается. См. [Пределы, стоимость и журналы](06-limity-i-zhurnaly.md).

Схема серверов и песочницы `home.run`: [CONTRACT.md](../../CONTRACT.md), разделы Built-in tools и OS sandbox.
