# Разрешения

С версии 0.2 блок `access` в `agent-config.yaml` обязателен. Без него профиль не загружается. Пустой блок ничего не разрешает: ни инструментов, ни папок, ни программ.

Список задаётся в `access` и повторяется именами в `skills.dsl`. `init` записывает узкий набор: читать `in` и `out`, писать в `out`, без запуска программ.

```powershell
kbshff config --project-root . --agent demo tools effective
```

`--connect` дополнительно опрашивает MCP. Имя инструмента полное, вида `home.read`. Короткое имя отклоняется.

## Действия

`access.tools.builtins` перечисляет встроенные действия. То же имя должно стоять в `allowed_tools` умения. Нет имени хотя бы в одном списке — модель его не видит.

Шаблон `init` открывает `home.list`, `home.read`, `home.write` и `config.*`. `local_tools.*` и `home.run` добавляют отдельно.

```yaml
access:
  tools:
    builtins:
      - home.list
      - home.read
      - home.write
      - home.run
      - local_tools.search_docs
      - local_tools.read_file
  filesystem:
    home:
      read: ["in", "out"]
      write: ["out"]
    workspace:
      root: "."
      read: ["src", "docs"]
    input_roots: ["./inputs"]
  run:
    programs:
      - name: python
        executable: "C:\\Path\\To\\python.exe"
        allow_children: true
```

`name` — имя для модели. `executable` — файл на компьютере. Относительный путь считается от каталога `agent-config.yaml`. Те же имена добавляют в `allowed_tools`. Иначе `tools effective` их не покажет.

### legacy

Явный режим для старых профилей. Чтение и запись рабочей папки и поиск по репозиторию широкие. `home.run` модели не предлагается. Рядом с `mode: legacy` нельзя задавать `tools`, `filesystem` и `run`.

```yaml
access:
  mode: legacy
```

Для нового агента оставляйте строгий список.

## Входные файлы

`--files` добавляет текст в запрос модели. Копии в рабочей папке нет, встроенные инструменты этот файл не меняют. В контексте файл обрезается до 50 000 символов.

В строгом режиме каждый файл лежит под одним из `access.filesystem.input_roots`. Каталоги должны существовать к старту. Относительный путь считается от каталога конфига. Путь в `.kuibysheff/protected` отклоняется всегда.

## Папки

`filesystem.home.read` и `filesystem.home.write` — префиксы внутри рабочей папки прогона. Шаблон читает `in` и `out` и пишет в `out`. В начале прогона эти каталоги создаются.

`filesystem.workspace` — корень `local_tools`. `root: "."` — каталог конфига. `read` — префиксы внутри корня.

`--home` — относительный путь под `.kuibysheff`, например `homes/demo-task-2`. Абсолютный путь и путь в `protected` отклоняются.

Путь инструмента относительный, без `..`. Ссылка, которая после раскрытия выходит из разрешённой папки, отклоняется.

Отказ приходит как ошибка инструмента, например `PolicyDenied`. Файл не создаётся, программа не стартует.

## Программы

Пустой `access.run.programs` означает, что `home.run` ничего не запустит, даже если инструмент уже в списках. Каждая запись — псевдоним и файл.

`inherit_env` — имена переменных. Значения берутся из окружения процесса `kbshff` и в YAML не пишутся. `allow_children` по умолчанию `true`. `false` оставляет один процесс. `runtime_read_roots` открывает дополнительные каталоги только на чтение.

Пока потолки не изменены: 32 процесса, 32 аргумента, 4096 символов на аргумент, 200 000 символов вывода, 120 секунд.

Отдельного раздела сети нет. К модели процесс ходит только на `provider.base_url`. Серверы MCP ходят в сеть, потому что указаны в конфиге. `home.run` на Linux пользуется сетью компьютера, включая петлю. На Windows открыты исходящий интернет и локальная сеть, петля закрыта. Профиль пользователя, ключи SSH и глобальный git в эту среду не попадают.
