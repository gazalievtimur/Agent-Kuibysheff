# run, ACP и A2A

`run`, `acp`, `a2a` и пробный прогон в студии используют один профиль, одни разрешения и одну рабочую папку. Правка `agent-config.yaml` видна всем четырём входам.

`run` завершается после одного JSON. `acp` держит stdio. `a2a` слушает HTTP, пока процесс не остановят.

## run

Скрипт читает ровно один JSON со stdout. Диагностика и ход работы идут в stderr.

```powershell
kbshff run --project-root . --agent demo --prompt "Собери краткий итог в out/summary.md" --files .\README.md --run-id invoice-row-42
```

| Поле | Значение |
| --- | --- |
| `stop_reason` | `goal_reached`, `limit_reached` или `error`. При `error` код процесса ненулевой, JSON уже на stdout |
| `result` | Текст ответа |
| `usage` | Шаги, токены, миллисекунды и `usage.cost`. Попытки — в `usage.cost.requests` |
| `logs` | Пути журналов |
| `run_id` | Идентификатор. Без `--run-id` его задаёт Kuibysheff |

Ctrl+C и Ctrl+Break на Windows отменяют прогон и всё равно печатают JSON.

`--progress stderr` пишет на stderr по одной JSON-строке на событие: `thought`, `message`, `usage_summary`, `tool_start`, `tool_finish`, `done`. Stdout остаётся одним документом.

Несколько стадий — несколько запусков с разными `--agent` и `--home` и одним `--project-root`. Файлы между ними передаёт вызывающая сторона, обычно из `out` одной рабочей папки во вход следующей.

См. [docs/OUTPUT.md](../OUTPUT.md) и раздел Invocation в [CONTRACT.md](../../CONTRACT.md).

## ACP

Редактор или мост держат один процесс на агента и присылают реплики по очереди.

```text
kbshff acp --project-root . --agent demo
```

stdin и stdout — только JSON-RPC Agent Client Protocol. stderr читают отдельным каналом. Непрочитанный stderr может остановить процесс.

Процесс живёт, пока открыт канал. Конец stdin завершает его. Каждая `session/prompt` начинается без истории предыдущих реплик. Контекст кладёт мост: в текст реплики или в файлы рабочей папки до вызова. Файлы ответа по-прежнему пишутся в `--home`.

Пароли почты, токены мессенджера и соответствие пользователя агенту остаются в мосте.

В VS Code окно говорит с Agent Host, тот — с `kbshff acp`. Расширение записывает `acp.agents`. См. [extensions/vscode/README.md](../../extensions/vscode/README.md).

См. раздел ACP в [CONTRACT.md](../../CONTRACT.md).

## A2A

HTTP нужен, когда другой агент живёт отдельно и сам находит карточку.

```powershell
$env:A2A_TOKEN = "длинный-секрет"
kbshff a2a --project-root . --agent demo --token-env A2A_TOKEN
```

По умолчанию сервер слушает `127.0.0.1:8787`. Карточка: `GET /.well-known/agent-card.json`. Задачи: JSON-RPC на `/jsonrpc` и HTTP+JSON на `/rest`.

`--token-env` требует `Authorization: Bearer` на вызовах задач. Пустая или отсутствующая переменная не даёт серверу стартовать. Карточка остаётся открытой и объявляет схему Bearer. Без `--token-env` сервер рассчитан на петлю. `0.0.0.0` — только за обратным прокси и со своей проверкой доступа.

Принимается текст. Файлы и произвольные данные этот выпуск не принимает. Между задачами истории нет. Успех и `limit_reached` становятся завершённой задачей, ошибка прогона — неуспехом, отмена — отменой. Расход лежит в метаданных задачи, ключ `kuibysheff.usage`.

Исходящий клиент A2A, gRPC, подпись карточки и push-уведомления не входят в этот выпуск.

См. раздел A2A в [CONTRACT.md](../../CONTRACT.md).

## Event-MCP

Проверка вызывается из `event_mcp`, а не потому, что модель выбрала инструмент. Привязка не открывает инструмент модели и не обходит список умений.

Исполняются три стадии. Остальные имена зарезервированы и в этой версии не вызываются.

| Стадия | Что можно заменить |
| --- | --- |
| `context.before_model` | Снимок сообщений перед запросом. История прогона не меняется. Пустой список, смена роли первого сообщения и удаление исходного поручения отклоняются |
| `model.after_response` | Текст ответа до разбора указания. Токены и цену обработчик не меняет |
| `run.before_output` | Итоговый текст. Расход, причину остановки, идентификатор и пути журналов не меняет |

Обработчики стадии идут по порядку списка. Выход первого становится входом следующего.

```yaml
event_mcp:
  events:
    context.before_model:
      handlers:
        - id: redact-secrets
          target: security.redact
          timeout_ms: 3000
          on_error: abort
```

`target` — инструмент MCP, который сервер уже отдал в списке. Необнаруженная цель не проходит проверку конфигурации.

| `action` | Результат |
| --- | --- |
| `pass` | Данные остаются |
| `replace` | Подставляется `payload` |
| `reject` | Цепочка и прогон останавливаются |

Сбой связи, таймаут или кривой ответ — техническая ошибка. `on_error: continue` оставляет последний годный снимок. `on_error: abort` останавливает прогон. Отмена прогона останавливает цепочку и при `continue`.

В журнал MCP пишутся имена, размеры и длительность. Текст поручения и ответа туда не кладётся.

`billing.mcp` к этой цепочке не подключается.

См. [docs/EVENT_MCP.md](../EVENT_MCP.md).

## Границы

Агент выполняет только перечисленные действия. Остальное возвращается отказом инструмента, без побочного эффекта.

`home.run` стартует в изоляции. Если изоляция недоступна, команда не запускается.

`.kuibysheff/protected` не читается как `--files` и не открывается файловыми инструментами. Ключ из `.env` в текст задания не подставляется.

Студия и `a2a` по умолчанию слушают только этот компьютер. Адрес `0.0.0.0` без своей проверки открывает задачи всем, кто до него достучится.

Сообщение об уязвимости: [SECURITY.md](../../SECURITY.md). Поддержка: [SUPPORT.md](../../SUPPORT.md). Ломающие изменения, включая обязательный `access` в 0.2.0: [CHANGELOG.md](../../CHANGELOG.md).
