# Протокол договорённостей (1C conveyor)

Читать **до** любых тестов и кода. Нарушение любой из четырёх инструкций → `blocked`, не «лучшая догадка».

Контракт стадии:

- `in/agreements-protocol.md` — этот файл
- `in/agreements.json` — идентификаторы банка (`id` + `expect`)
- `in/agreements.md` — заморозка аналитика (обязательна со стадии yaxunit)
- `in/expect.json` — то же `expect`, что в JSON

Идентификаторы — **литералы**: имена процедур, объектов метаданных, обработчиков. Смысл (как добиться эффекта) можно реализовывать. Строку-идентификатор менять нельзя.

## 1. Нет фиксации

- Нет `in/agreements.json` → не писать тесты и не писать прикладной код. Только `blocked`.
- **1c-analyst:** первый deliverable — `out/agreements.md`. Пока его нет, остальные файлы плана не считать готовыми.
- Downstream без `in/agreements.md` → `blocked` (не выдумывать имена).
- Пропускать эти файлы нельзя: «потом» и «очевидно из плана» не замена фиксации.

## 2. Неточная фиксация

- Копировать идентификаторы **посимвольно** в backticks.
- Запрещены синонимы, перевод, транслит, «эквивалентное имя», сокращения, перестановка слов (`Тест_НулевоеКоличество_Отказ` ≠ `Тест_КоличествоНоль_НеЗаписывается`).
- Brief и `agreements.json` / `expect.json` расходятся → `blocked`. Не выбирать вариант самостоятельно.
- `tasks.md` повторяет gate-процедуру **дословно**, не вместо `agreements.md`, а вместе с ним.

## 3. Разная интерпретация

Два слоя, не смешивать:

| Слой | Примеры | Правило |
| --- | --- | --- |
| Литерал | `Тест_КоличествоНоль_НеЗаписывается`, `РасходТовара`, `ПередЗаписью` | Не интерпретировать. Писать как в контракте. |
| Смысл | «запись должна быть отказана» | Реализовать эффект; не подменять литерал. |
| Явный OR | `&Вместо` **или** `&ИзменениеИКонтроль` | Любой из списка. Это не право заменить третий синоним. |

Тесты: проверять **эффект** `Записать` (отказ платформы / исключение / документ не записан). Запрещено считать успехом локальную переменную `Отказ` рядом с вызовом, если она не связана с записью.

## 4. Пренебрежение

- `done=true` только после **таблицы сверки** в отчёте стадии: договорённость → где в артефакте (файл + идентификатор).
- Нет сверки = не `done`.
- «Улучшить имя теста», «более понятный синоним», «в плане другое» = нарушение.
- Extra-тесты разрешены. Gate-процедуру из контракта **не переименовывать и не опускать**.
